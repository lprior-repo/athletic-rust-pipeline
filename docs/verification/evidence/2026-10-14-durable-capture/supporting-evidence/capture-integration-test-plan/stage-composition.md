# Actual Results-stage ownership boundary

2026-10-14 05:48 UTC. Static source review only, not an async approval or execution claim.

## Findings for Root

1. Staged `census-service/src/restate_services/jurisdiction/stage_runs.rs:48-74` acquires `self.jobs.admit_work(ctx.key())` before `ctx.run`, then moves WorkAdmission into `region.blocking`. The guard lives inside the blocking job around `Handle::block_on(jobs::results_stage(...))`. The latest staged proposal uses `region.blocking` directly and preserves `HandlerError` in `Outcome::Err`; it no longer flattens every result into `JobError::Terminal`.
2. `jobs::results_stage` is the `results_arms::results_stage` re-export. Its reached `selection::select -> collect_source -> collection::collect/one -> milesplit_results` chain contains no call to `Jobs::permit`, `admit_work`, or the original `ctx.key` gate. Thus the inspected code does not recursively acquire its own Jobs resource or work-key guard. This is a static claim with the checked boundary, not proof of no possible wait cycle.
3. The selector does await an independent one-worker semaphore and then `tokio::task::spawn_blocking` in `results_arms/selection.rs:22-36`. That is a nested dependency on Tokio's blocking pool while the outer worker is in `Handle::block_on`. It does not re-enter the Spawner blocking semaphore. A one-thread Tokio blocking-pool configuration could deadlock this topology; it is not the production default and no production deadlock was observed. The required narrow regression uses **Spawner capacity=1**, not a silently changed runtime topology. Root may separately decide whether single-thread blocking-pool support is required or document/test the supported bound.
4. `spawn/blocking.rs` moves the job into its supervised `push_blocking` closure before awaiting the oneshot reply. Caller-future drop drops the receiver, not the running job. The job's guard is released only when actual stage work unwinds/returns. Normal completion, domain error and panic classification must remain distinguishable; timeout does not imply a blocking job stopped.
5. Inspected pinned SDK 0.12.0 source is `toolchain/cargo/registry/src/index.crates.io-1949cf8c6b5b557f/restate-sdk-0.12.0/src/endpoint/context.rs:1017-1079` under the recovery directory. `RunFutureImpl` takes its closure and invokes it only for `AwaitResponse::ExecuteRun`. On already-recorded result or cancellation, it transitions to `WaitingResultFut` and drops the unused local closure, so its captured WorkAdmission is released. Admission still occurs *before* the journal is consulted; a replay appropriately waits behind a live predecessor, but must not leak its own unused guard after the replay result returns.
