# Scope, authority and historical limitations

1. This evidence concerns sealed capture-to-owned-parser runtime envelopes. It does not adopt structural-open behavior, Prepared recovery v2, an installation enrollment/migration, new source families, policy/schema versions, or a new persistence protocol.
2. The context guard checks historical-versus-durable variants only. A privileged internal caller could pair retained envelope A with another DurableV1 context B and pass this guard. It also receives a separately parsed meet ID. The guard is not an exact owner/store/work/profile/year/meet identity witness. Root explicitly retained this limitation; review PE-4 records `owner_approved_no_action`.
3. Exact binding was traced only through the current two production acquisition-to-interpretation call chains and immutable private Run context. No currently reachable production injection/context-switch path was found in that graph. This is narrower than a universal guarantee over future callers. Public provenance views are descriptive and never confer construction authority.
4. Private fields do not create cryptographic authority. Actual retained authority still depends on the verified producer paths, bounded actual-byte verification and same-body ownership described in the contract/review. Pure parsing, deserialization of raw captures and the cfg(test) historical factory do not create retained authority.
5. Releasing the resident Vec preserves the interpretation's original metadata and verdict. The outcome then represents a historical interpretation with metadata; it is not a complete resident verified transport input and cannot convert back to retained `CapturedFetch`.
6. This is an intentional Rust source API tightening. Direct field/enum construction and caller-assembled trusted outcomes are removed; current consumers migrate to methods/views. No runtime compatibility shim, persisted migration or semver-compatible source API claim is introduced.
7. Historical source/payload preservation has static evidence and selected exact passing regression oracles. Those scenarios do not prove all historical stores, all possible payloads or all unexercised consumers.
8. Opaque envelopes do not certify provider ownership, complete meets, canonical identity, cohort eligibility, current backing existence, recruiter publication or census completion. These require their own evidence-use/acceptance contracts.
9. First test compilation failed with seven E0308 errors. The corrected second, third and fourth attempts ended with rustc SIGKILL; no verified cause is recorded. Host memory observations do not establish an OOM cause. All four complete failed logs are preserved. The third attempt's intended environment debug override did not take effect; actual rustc still used `debuginfo=line-tables-only`. The fourth attempt explicitly forwarded `--config 'profile.test.debug=0'`; the raw compiler invocation confirms the override took effect, but the process still terminated with SIGKILL. Those attempts remain failures. The fifth scoped invocation subsequently passed 107/107 under explicit debug=0 and compiler threads=1 requests; this does not establish the causes of the earlier terminations.
10. Source review, source hashes, exact test definitions, successful formatter writes and intended negative compiler outcomes are distinct from executed acceptance. No zero-test run, prepared probe, partial log or successful compile is counted as a behavior test pass.
11. No benchmark/throughput improvement, allocation budget across the full pipeline, native fault durability, fuzz campaign, full async review, release gate, full October 11 specification verification or production publication is certified here.
12. This evidence assembler performs no repository writes, builds, tests or publication. It copies scoped evidence into a detached proposal. Source commit binding is verified. All scoped executions are terminal. Strict-size and module-seam failures remain open; the required active-context truth-serum audit remains unavailable.
