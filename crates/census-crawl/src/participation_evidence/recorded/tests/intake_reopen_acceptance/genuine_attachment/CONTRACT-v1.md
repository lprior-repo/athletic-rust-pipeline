# Genuine attachment fixture contract v1

This is explicit-review mechanism and capacity test coverage over retained genuine
sources. The controlled approval bytes are not an authenticated human decision to
attach the named person's documents. No new publisher qualification, provider
ownership, school affiliation, performance projection, report descriptor or frozen
publication is established by this fixture.

The source-only baseline is commit
`1ca29fe1138d54529b535afb3e04c13af3e59b05`. Required review inventory SHA256 is
`ffe74266d46b4d0324f511a55a90a4cb9fc0d4be4b4fbdf6fff023b2ac23b2f4`; source inventory
SHA256 is `fcbbee47cc88bd078a5c843dfb9807971128fdb05015575c647fcecf4fe55e21`.
`SOURCE-REFERENCES-v1.json` records independently verified original-body equality,
literal spans and source-derived preimages. It is not a checked-reader execution
or an issued reference inventory.

## Actual target and originals

The test reuses `accepted_provider::installed::install()`, then calls the actual
`PublicIdentityWriterV1::establish_source_bound` with its installed candidate,
current revision and actual writer head. The public ID comes only from the writer
outcome. `Installed::verify()` retains the original provider installation oracles.

Four original roots are read through their existing checked recorded readers:
ProviderSchoolPacketV1, SourceTargetPacketV1,
IndependentParticipationPacketV1 and HtmlResultCaptureV1. All seven supported
CaptureJson and OriginalBody pairs are retained-leaf descriptors referencing those
actual installed roots. Original capture bytes are extracted from the installed
raw JSON without reencoding them. The unsupported DCC person-roster capture and
full body are bounded Inline objects, retaining the original transport metadata,
headers, body and canonical/request mismatch. All eight body fixtures were
independently compared with their recorded originals.

The complete original May15 capture and all parsed result diagnostics are retained
in A. A does not eagerly create B-only proposed subject/interpretation objects.
All negative and competing context remains present in both current scopes.

## Exact object encoding and ownership

`AttachmentObjectReferenceV1` is SHA256 of the exact bytes plus their exact u64
length. Deduplication is by digest, with byte-length equality and exact equality
when both materials are Inline. JSON DTOs use only
`census_domain::model::serialized_bytes`; no handwritten substitute encoder issues
a checked reference. String preimages have no terminal newline.

- Document subject bytes are the checked reader's exact preimage:
  `document_subject_v1\n{namespace}\n{native_document_id}\n{url}\n{body_sha256}\n{locator}`.
  The constructor asserts the digest equals `DocumentSubjectV1::reference()`.
- A is document-owned namespace `mhsaa_article_v1`, native document `28974`,
  locator `html_bytes:113861:113927`, role AthleteStatus. Its interpretation bytes
  are `mhsaa_subject_dcc_event_day_v1\n{proof.capture}\n{proof.locator}`, asserted
  against the checked proof. Its context is the complete article DTO.
- Each provider-linked CHSL subject is an explicitly test-authored canonical DTO
  with schema, authorship, actual person/school/name, checked packet reference,
  original capture/body, exact row fact, locator, interpretation, complete proof,
  event code, result document ID/URL and meet ID. It does not invent a provider
  result-row ID. Each interpretation uses the actual checked proof's exact string
  preimage and is compared with the reader's interpretation digest.
- B has three distinct document-owned ResultRow subjects, namespace
  `milesplit_result_document_v1`, native document `1304896`, for original row
  ordinals 527, 540 and 572. Each interpretation is the actual reader's canonical
  tuple `(retained-milesplit-html-result-row/v1, requested_url, body_sha256, locator)`.
  Its digest must equal the row reader's reference. Each subject has its own exact
  raw-row fact and corroboration pair. The common result context uses the actual
  reader's canonical tuple of marker, complete capture, parsed meet, skipped rows,
  grade issues, published start and published end; its digest must equal the
  checked document context reference.
- Literal facts use the complete original byte spans in SOURCE-REFERENCES-v1.json.
  A's paragraph includes both CHSL hurdle marks; neither CHSL row is omitted.
  B's original Senior/dual-hurdles target context is the contiguous 667-byte span
  at 113861, digest `7913637b4dc9a7e3e1d84df3741eec0ab0102361795a30f5dede010780661b57`.
- Three publisher-lineage DTOs keep MHSAA, MileSplit and DCC publication context
  separate. They include exact original request/capture/body/acquisition data and
  explicitly state that the receipt is not a publisher. No independently issued
  upstream-producer qualification is fabricated.

## Complete diagnostics and current facts

The six diagnostics serialize the existing reader outputs without substituting
an authority token: complete article and visible headings/paragraph spans;
profile and both linked rows plus the entire visible row scan; complete directory
and provider roster with rejections and unfinished work; original DCC ownership
refusal; every parsed May15 event/row/skipped row/grade issue; and the complete
accepted target/source/candidate/decision/history scope.

The accepted-target DTO includes all six public input-table revision counters and
all actual Inspection-issued object references. Private token baseline fields are
not reconstructed. The full typed token is protected by equality, and the actual
issued opaque token/capture objects are retained and verified by the Store route.

Each stage contains these eight scoped facts:

| Fact | Documentary subject | Disposition |
| --- | --- | --- |
| Complete article context | Actual article DocumentSubject | ContextOnly |
| Profile and both CHSL row context | Profile CaptureJson | ContextOnly |
| Raw Person.gender Female | Profile CaptureJson | ContextOnly |
| October roster absence | Provider-roster CaptureJson | Unavailable |
| DCC canonical/request mismatch | DCC-roster CaptureJson | Unavailable |
| Complete raw May15 context | May15 CaptureJson | ContextOnly |
| Accepted target inventory | Actual issued accepted-target witness | ContextOnly |
| Dated schedule context | Schedule CaptureJson | ContextOnly |

These document subjects never substitute for person identity. Raw Person.gender
is not mapped to a competition category. Current roster absence does not imply
historical departure. Schedule and A's receipt are not independent publishers.

A adds the original person-specific paragraph and both exact CHSL row facts, with
two IndependentPersonSpecificContext pairs. B adds each of its three original row
facts and the original Senior/dual-hurdles target fact, with three separate
IndependentPersonSpecificContext pairs. Distinct May15 marks are never presented
as an exact-result cross-reference. B does not redundantly relabel A's three
positive facts ContextOnly: the original positive facts remain in actual A's
verified record, complete scope, material and receipt.

## Finite current and prior closure

The complete-scope DTO contains all four root descriptors, every original
capture/body reference, all source material references, diagnostics, current facts
and dispositions, subjects/pairs, actual prior inventory/records/receipts/object
references, and actual inspection references. It never contains itself or the
current attachment record. Earlier scopes refer only to earlier records, making
the closure finite. A scope hash never substitutes for missing source bytes.

B is constructed only after A actually writes and reads back as the one active A.
It explicitly compares A's complete article subject and accepted target with B's
reconstructed original article subject and current inspection target. The exact
record, receipt and inventory are retained. Every current directly referenced
role is declared in B. Other original objects resolve through the fully verified
prior ledger. Every material in the complete source catalog must be either a
current declared reference or an exact prior reference. Borrowed preparation
supplies only current declared objects absent from the prior ledger.

## Counts, grant observations and preservation

Before any bounded list conversion the emitter records the actual deduplicated
six-category formula: subjects + objects + facts + pairs + scopes + accepted-target
subjects. Source-only expected shapes are A `1 + 44 + 11 + 2 + 1 + 2 = 61` and B
`3 + 38 + 12 + 3 + 2 + 1 = 59`, contingent on actual issued references and digest
deduplication. These are not observed admission or fit results. No cap is raised,
required source is omitted, or active A synthesized when admission refuses.

Each operation transfers one unchanged opaque fixed grant from inspection through
preparation and application. There is no public per-phase usage getter. Actual
public-route success/refusal is reported with its phase and typed error. The
separate source-construction read grant and independent command-approval control
grant are labeled as such and never claimed as workflow phase measurements.
A capacity refusal returns an error and remains an acceptance delivery blocker.
If A refuses, B is blocked; its target or attachment is never fabricated.

Within an open Store, refusal/replay checks compare held exact source and attachment
namespace fingerprints through `same_contents`, every retained logical payload,
every receipt value, table digest, full input revision token, accepted head and
evidence/derived generations. Across close/reopen, they compare complete owned
logical payloads and receipts, not engine sequence or cross-origin fingerprints.
Original roots and accepted-provider installation oracles are rechecked.

## Execution and output contract

The integrator owns registration, formatting, compilation and native execution.
No build, formatter or runtime selector was run while authoring this packet.
Two tests are authored: the full A-then-B/reopen/replay acceptance test and a
six-positive-fact literal inventory check. The latter issues no Store capability.

Every runtime report is emitted as `GENUINE_ATTACHMENT <name> <canonical JSON>`.
When `CENSUS_GENUINE_ATTACHMENT_EVIDENCE_DIR` is set to the authorized output
directory, the same reports plus exact source-object bytes and retained-leaf
descriptors are written there. Preconversion counts/catalog appear even if a
bounded list conversion subsequently refuses. Inspection-issued bytes stay
opaque; only actual returned references are reported. Root, inspection, active-A,
command and scope references remain unresolved until that actual execution.
