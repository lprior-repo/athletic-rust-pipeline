### Whole-meet row inventory (ground truth, meet 634313 + 667509)

`flatEvents[].results[]` fields observed non-null: `IDDiv, Place, Exhibition, JD, Round, pr, sr, EventID,
PersonalEvent, EventTypeID, SortIntRaw, SortIntTemp, ShortCode, disPlace, disGrade, disAthlete, disTeam,
Score, IDResult, Result, SortInt, Official, AthleteID, FirstName, LastName, Grade, AgeGrade, TeamID,
SchoolName, Gender, EditorID, hasSplitsSeries, MediaCount` (+ `AthleteName` on relay rows).

- **Grade is present per row** (`Grade`, `AgeGrade`) — the whole-meet pull is a Grade-11 source by itself.
- **Relay membership is enumerated**: relay rows carry `PersonalEvent:false` and `AthleteName` = `"<BR>"`-joined
  leg names; the top-level `relayLegs[]` array resolves each leg: `{ResultID, ID, AthleteID, Name, ShortDesc(=grade), split}`.
- **Implement/hurdle spec** lives in `eventTypes[]` (`{eventId, IDEventType, Description}` — e.g. `39" / 0.991m`, `36" / 0.914m`, `12lb`, `1.6kg`) and `isHurdle` in the event-division payload.
- **Wind / Heat / HeatPlace** appear in the per-event `GetResultsData3` rows when the meet recorded them (verified on meet 615580: all 33 rows have `Wind`), and are absent from the bundled payload.
- Field events: attempts are NOT in the default row set; rows carry the best mark (`Result` like `61' 3.5"`) + `Measure:"E"`.

### Token model (do not persist values)

- `jwtMeet` — meet-scoped JWT **minted by the public `GetMeetData` response** and echoed as `anettokens`. Not a user credential.
- rankings `anettokens` — `aud=jwtTFTopReport`, `userId:0`, `userRoles:[]`: an **anonymous session token** minted by the page bootstrap. `anet-site-roles-token` is likewise `userId:0`.
- The SPA's `GetNavInfo` calls additionally send `anet-appinfo: web:web:0:300` and the session cookies (incl. `cf_clearance`).
- **Rule reaffirmed: never persist `jwtMeet`, `anettokens` or cookie values.** All saved evidence in
  `evidence/gap-closure/` is token-redacted.

### Gotchas found the hard way

1. `GetResultsData3` requires **lowercase `gender` (`"m"`/`"f"`)**; `"M"` returns HTTP 200 `{"currentEventValid":false}`.
2. It is POST-only (GET → 405).
3. Throws use their own shorts (`shot`, `discus`) — `SP` is invalid.
4. `GetMeetData` without `meetId` → 404 route-match error; with an unknown meet → valid JSON, empty divisions.
5. `GetNavInfo` is the only rankings endpoint that stayed 403 for a plain client (session-bound).

### Consequence for the acquisition plan

- **Whole-meet pulls over plain HTTP (3 requests/meet) replace fighter per-athlete refreshes** — no headed
  browser needed for meet results; the browser is only needed for `GetNavInfo`-class session calls.
- Compare measured cost: baseline 43,423 AN requests (2,728 discovery + 40,695 profiles) vs
  `GetAllResultsData` = 3 requests/meet with `Grade` per row.
- A weekly meet-centric refresh can diff `IDResult` sets per meet instead of re-pulling profiles.

## §3 AthleticLIVE closures (B1–B5) — zero `athletic.net` requests

**B5 — tenant universe (was: scripted 258 requests). CLOSED with 1 request.**
`POST https://search.athletic.live/*/_search` with `{"size":0,"aggs":{"tenants":{"terms":{"field":"_index","size":300}}}}`
returned 296 buckets → **256 `<tenant>_meet_list` indices** with doc counts:
`live_results 75,401 · athleticlive 18,009 · athletic_timing 4,376 · wayzata 2,769 · fulton 2,384 ·
xpress 2,162 · michiana 1,995 · blacksquirrel 1,877 · adkinstrak 1,698 · aatiming 1,344 · iptt 1,212 ·
heros 1,117 · shazam 1,032 · lexicon 921 · dakota 916 · …` plus global `athlete_list`, `team_list`,
`search_record`, `field_app_round_list` and 40 `media_items_*` indices. Evidence:
`evidence/gap-closure/athleticlive-es-tenant-buckets.json`.

**B4 — AthleticLIVE ↔ Athletic.net meet-ID mapping. CLOSED.**
Meet docs carry both ids: `i` = AthleticLIVE meet id, `ani` = **Athletic.net MeetID** (nullable; `null`
when the tenant never linked the meet), `aci` = AN calendar id, `atr` = timer credit string, plus
`an/axn/aan/atn` link flags. Live example (wayzata_meet_list): `i:38426, ani:562093`.
So the tenant→AN meet join needs **no AN request at all**. Evidence:
`evidence/gap-closure/athleticlive-es-meet-sample.json`.

**B2 — blob container listing: CONFIRMED DISABLED** (`$web?restype=container&comp=list` → 404
`ResourceNotFound`). Index discovery must come from ES (above); per-document blob GETs stay public.

**B3 — change detection on the blob store: CLOSED** (report 12, re-confirmed by the field evidence):
`ETag` + `Last-Modified` returned, `304` honored → zero-byte revalidation for weekly refresh.

**B1 — `api.athletic.live` shape:** the product's data path is **ES (`search.athletic.live`) + Azure blob
(`athleticlive.blob.core.windows.net/$web/...`) + Firebase RTDB (`trackmeet-io`)**; the tenant SPA does not
consume a REST API on `api.athletic.live` (that host answers `Cannot GET /api/meets` but is unused by the
app). Documenting the ES bodies + blob doc types (33 paths) is the API surface. Caveat recorded while
capturing: **AthleticLIVE pages also load app assets from `livestatic.athletic.net` and an `edge.athletic.net`
call** — treat those hosts as Athletic.net for compliance purposes; the ES/blob/Firebase data path is
independent of them.
